### Fixed
- **A rejected Hardcover token no longer costs a request per row** (#3101). When Hardcover refuses the saved API token (a 401, or a 403 that is an authentication failure), Bindery now stops asking with that token. A bulk import, discovery sweep, catalogue sync, list sync or scheduled refresh stops at the first rejection and says "Hardcover rejected the API token", instead of sending one doomed request for every row. Settings shows a notice, saving a new token lifts the pause immediately, **Test connection** still reaches Hardcover so you can retest after fixing the token, and one probe request an hour lets a restored token recover by itself. Server errors and queries Hardcover refuses for other reasons do not pause anything.
