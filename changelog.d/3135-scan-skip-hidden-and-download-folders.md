### Fixed
- **Library Scan leaves torrent folders and other non-library folders alone** (#3135). A torrent client saving into the library (for example `/data/audiobooks/.torrents`, so imports can hardlink and keep seeding) made the scan find every torrent copy again and list it as an unmatched book, one click from importing it or moving it out of the client's folder. The scan, the "already in the library" check and folder import now skip known junk and sync folders (`.torrents`, `.Trash-*`, `.incomplete`, `.AppleDouble`, `.stfolder` and similar), the configured download folders when they sit inside a library folder, and any folder holding a `.binderyignore` file. Other folders that start with a dot are still scanned, because a book folder can be named that way (`...And Then There Were None`, `.hack Sign`); put a `.binderyignore` file in one to skip it. Entries an earlier scan listed from those folders disappear on the next scan.
